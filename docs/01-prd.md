# 食衡产品需求文档（规格冻结版）

版本：1.0.0　产品形态：openvela 可穿戴快应用　状态：冻结

## 1. 产品定义

食衡面向容易忘记记录饮食的年轻用户，以餐时提醒、腕上快速确认和离线能量账本降低记录成本；无网络、无手机、无 AI 服务时仍可完成核心闭环。

### 目标

- 应用每次打开或恢复时，用餐时胶囊结合当前时间段和当天记录主动提示。
- 典型一餐在 30 秒内完成记录；最近吃过和收藏套餐均可快速复用，任何写入都先进入确认页。
- 离线提供已记录食物摄入、每日饮食参考线对照、连续记录天数和最近 7 天回顾。
- 明示热量为估算，所有建议仅供生活管理参考。
- 在兼容环境用 `service.health`、`system.alarm` 和 VelaClaw 增强体验，但 P0 主流程不依赖它们。

### P2 / 明确不做

- 真实腕上录音和云端 ASR。
- 自建云服务器。
- 手机伴侣 App、蓝牙同步、小米运动健康写入。
- 云账号和多设备同步。
- 拍照识餐和条码扫描。
- 系统级灵动岛或后台常驻；餐时胶囊只是食衡前台页面内的普通组件。
- 医疗诊断、减重疗效或精确代谢预测。

模拟器 Mock、文本演示和估算数据必须标明来源及边界，不能宣称未实际跑通的系统能力已经可用。

## 2. 核心场景与闭环

早餐、午餐、晚餐或加餐前后，用户打开或恢复食衡，看到当前餐次状态，优先用一句转写文本描述刚吃的食物，或切换到最近吃过、收藏套餐和目录备用入口，检查份量与估算值后确认保存；首页和历史立即展示基于已记录餐食的摄入对照。

核心闭环：`打开/恢复 → 餐时胶囊 → 选择或输入 → 确认 → 保存 → 今日账本`。

## 3. 功能优先级

### P0：参赛交付闭环

1. 首次设置：只设置每日饮食参考线、早餐/午餐/晚餐时间段并接受免责声明。默认 2000 kcal 作为成人食品营养标签对照值，不是个人饮食处方，也不要求必须吃满；编辑范围 1200–4000 kcal、步长 100 kcal，低于 1500 kcal 时提示建议在专业人员指导下设置。旧数据中的体重字段只为兼容而保留，新用户不再填写。默认时间段为早餐 07:00–09:30、午餐 11:30–14:00、晚餐 17:30–20:30。
2. 餐时胶囊：应用每次打开或恢复时按当前时间段与当天对应餐次记录判断状态。未记录时展开，提供“现在记录 / 稍后提醒 / 本餐跳过”；已记录时收缩并显示该餐热量。稍后提醒保存下一次提示时间；当天跳过、稍后和完成状态须可区分。
3. 60 项本地食物目录：交付验收固定 60 项稳定 ID，覆盖常见类别，使用单一每百单位能量事实源，每项记录数据来源；第三方数据和素材最终列入 `THIRD_PARTY_NOTICES`。
4. 快速记录：记餐页默认首先显示“一句话记餐（模拟器转写模式）”，用户也可切换到“快捷选择”使用最近吃过、收藏套餐和分类目录。转写文本不是录音或语音识别。台湾卤肉饭、番茄炒蛋盖饭、鱼香肉丝盖饭和牛肉面按本地常见份量模板展开为可编辑组成项；所有模板必须显示估算边界。典型一餐目标在 30 秒内完成；收藏套餐不超过 3 次点击即可进入确认页，仍须确认后保存。
5. 确认后保存：确认页显示餐次、食物、实际份量、逐项估算和合计；点“确认保存”前不得写正式账本，取消不留记录，重复提交幂等。
6. 今日饮食记录：首页以“今日已记录”为主数字，用一条进度条对照每日饮食参考线，同时显示三餐状态和连续记录天数。只表示用户已保存的餐食，不生成健康评分。
7. 记录维护：餐食可修改、删除；操作后首页汇总和历史立即回算。
8. 最近 7 天：顶部只展示有记录天数和仅按有记录日期计算的平均摄入；每日明细只显示已记录餐数和摄入。所有指标依赖记录完整度，不作营养诊断。
9. 始终可用的本地建议：根据记录情况输出温和、非医疗的规则化提示。
10. 设置：编辑饮食参考线与三个餐段，查看隐私声明，清除全部本地数据。

### P1：可选增强

1. `service.health` 系统健康数据卡：本次比赛接口仅开放 HEART_RATE、SPO2、STRESS，按官方 Mock 流程覆盖；拿不到系统步数、运动记录或活动热量汇总。仅页面可见时读取或订阅，离页取消。心率、血氧只展示；压力只可触发温和本地建议，不进入热量公式、不持久化、不诊断。`$canIUse` 为 false 或错误码 203 时显示“当前设备暂不支持”，订阅 fail、同步异常等读取错误显示“健康数据暂时读取失败”，callback 收到形状错误、非有限值或超出官方 Mock 范围的样本显示“暂无有效健康数据”；三类状态均不影响主流程，后续有效样本可正常覆盖。

长期产品方向是在官方提供可靠读取接口后接入系统步数、运动记录或活动热量。初赛版本不提供手动运动补录，不生成运动 Mock，不从心率或原始传感器数据反推消耗，也不宣称已实现系统运动同步。
2. VelaClaw 建议：仅由用户主动触发；10 秒失败或超时回退本地建议。应用绝不接收或存储 key，用户只在 goldfish `ai_agent` 官方配置界面私下输入 `tp-` key；不向 AI 发送不存在、推断出的健康或个人数据。
3. `system.alarm`：仅当能力可用时申请系统闹钟。不可用时，“稍后提醒”仍保存下一次提示时间，并在应用下次打开或恢复时判断和提示。该能力不是 P0 阻塞项。

## 4. 页面与导航

共六个路由页面：入口、首次设置/设置、首页、记餐、确认和历史。

```text
首次设置 → 首页
首页 → 记餐（一句话记餐默认 / 快捷选择备用）→ 确认 → 首页
首页 → 历史（页内展开日明细）
首页 → 设置
```

餐时胶囊、今日看板、建议和系统健康数据卡均在首页；一句话记餐是记餐页默认模式，最近项、收藏和目录位于“快捷选择”模式；不为一次性功能新增主要页面。

## 5. 关键交互

### 首次设置

1. 每日饮食参考线预填 2000 kcal，可在 1200–4000 kcal 间以 100 kcal 调整；页面始终显示当前数值、与 2000 kcal 标签参考值的差异，并明确它不是个人处方。原存储中 800–5000 kcal 的历史值仍可读取，超出新编辑范围时只有用户保存才更新。
2. 三个餐段预填早餐 07:00–09:30、午餐 11:30–14:00、晚餐 17:30–20:30，可修改且需校验。
3. 用户阅读并接受免责声明后完成设置；完成状态持久化，重启不重复，设置页可修改上述内容。

### 餐时胶囊与提醒

- 每次应用打开或从后台恢复时重新判断当前本地时间、当天该餐记录和 `mealPromptState`。
- 当前餐未记录时展开，提供“现在记录 / 稍后提醒 / 本餐跳过”；已记录时收缩并显示该餐热量。
- “稍后提醒”由用户选择下一次提示时间并保存。仅当 `system.alarm` 可用时申请系统闹钟；失败或不可用要如实提示，仍在下次打开/恢复时判断。
- “本餐跳过”只影响当天该餐提示；新增、修改或删除餐食后应重新计算该餐状态。

### 目录与快捷记录

- 目录作为“一句话记餐”之外的备用模式，用户主动切换到“快捷选择”后才显示。
- 快捷选择默认提供“全部（60）”和带数量的分类；当前已选区位于目录上方，支持减量、加量、移除和清空，重复选择同一食品合并增加份量。
- 食品目录以 `energyKcalPer100` 为唯一能量事实源，份量只是输入方式，不另存一套基准热量。
- 最近吃过和收藏套餐均为 P0；选择后必须进入确认页，不能一触即写入。
- 收藏套餐目标是不超过 3 次点击进入确认；整餐流程以 30 秒内完成为验收目标，不以固定点击数限制所有入口。

### 一句话记餐（模拟器转写模式）

该模式是记餐页默认入口，无需滚动查找。为保证比赛镜像稳定，初赛界面使用官方文本选择器选择明确标记的模拟器转写示例，再交给本地确定性解析器；入口醒目标注“不是录音或语音识别”，不得出现麦克风、录音波形或“录音中”等暗示。

- 输入最多 80 字、最多解析 12 个片段；规范名和别名按最长匹配优先。
- 仅整段消费匹配文本，支持有限中文/阿拉伯数字，以及每个食品条目明确声明的单位。
- 只有完全没有数量时，才可使用界面明确展示的默认份量。
- 数字无单位、单位不支持、未知词、否定语义均保留为待处理，禁止静默保存或模糊猜测。
- 常见套餐模板只接受默认、半份、一份或两份；“少饭、不要蛋、加肉”等个性化修饰必须进入待处理状态，用户可在模板展开后手动调整。
- 解析返回 `complete | needs_review | empty`、`recognizedItems`、`unknownSegments` 和仅用于当次展示的 `assumptions`（同时保留设计兼容字段 `items/unresolved`），只产生内存草稿，无存储副作用。
- `needs_review` 必须由用户处理后方可进入可保存状态。

### 确认、维护与今日看板

- 餐食遵循“草稿—确认—提交”；返回、取消、超时、退出均不提交。
- 首次点保存后禁用按钮；同一记录 ID 只写一次。餐食支持修改、删除，完成后首页汇总和历史立即回算。
- 摄入 = 当日餐食千卡之和。
- 参考线差值 = 每日饮食参考线 − 已记录食物摄入。
- 首页主数字为“今日已记录”；进度条显示已记录摄入占参考线的比例，超过 100% 时视觉进度封顶并单独显示高出千卡。
- 连续记录以至少有一条餐食的本地日为计数单位；今日未记录时计至昨日，并明示“今天尚未记录”。
- 界面明确标注“估算”和“仅供生活管理参考”，不评价健康风险。

## 6. 数据、隐私与免责声明

- 档案、餐食、最近项、收藏和餐时提示状态默认仅存设备本地，最多保留 30 天；无账号、无手机同步。旧 V1 的运动记录字段只为兼容可读取，不再展示或参与计算。
- 损坏或未知版本状态不得覆盖，显示明确的损坏状态提示和清除入口。
- 清除须二次确认，完成后应用内不可恢复。
- VelaClaw 调用前展示实际将发送的最小文字摘要；不发送健康值、完整历史或不存在的个人数据，取消即不发送。
- 固定声明：“食衡中的食物热量和建议均为估算，仅供生活管理参考，不构成医疗、诊断、治疗或专业营养建议。如有疾病、过敏、孕期或饮食障碍等情况，请咨询合格专业人士。”

| AC-02 | 离线可浏览/搜索 60/60 条目；ID 唯一、每项有来源且仅有一个每百单位能量事实源。 |
| AC-03 | 典型一餐在 30 秒内完成；收藏套餐不超过 3 次点击进入确认，确认前记录数不变。 |
| AC-04 | 取消、退出草稿、双击保存分别新增 0、0、1 条。 |
| AC-05 | 记餐页首次打开直接显示一句话记餐；文本演示明示“不是录音或语音识别”；待处理片段解决前不能静默保存，快捷选择仍可切换使用。 |
| AC-05A | “台湾卤肉饭”展开为米饭 200g、红烧肉 100g、水煮蛋 50g、清炒青菜 80g，合计约 676 kcal；四个模板均可按半份/一份/两份缩放并在确认页逐项修改。 |
| AC-05B | 快捷选择显示 60 项总数和分类数量；误选项可在确认前减量、移除或清空，重复点击同一食品不产生重复行。 |
| AC-06 | 给定食品、实际数量和每百单位能量，单项及合计公式误差不超过 1 kcal。 |
| AC-07 | 旧状态中含体重和运动记录时仍可读取；这些字段不出现在新界面、饮食进度、历史或 AI 摘要中。 |
| AC-08 | 本地午夜正确归日；最近 7 个自然日明细与账本合计一致。 |
| AC-09 | 仅保留最近 30 个自然日，第 31 天旧数据在维护后清理。 |
| AC-10 | 断网且 health/alarm/VelaClaw 均不可用时，餐食、摄入对照、历史和本地建议仍可用。 |
| AC-11 | HEART_RATE、SPO2、STRESS 只在首页健康卡可见时读取/订阅并在离页取消；明确不支持、读取错误、无效样本分别显示“当前设备暂不支持”“健康数据暂时读取失败”“暂无有效健康数据”，后续有效样本正常覆盖；AI 10 秒失败回退。 |
| AC-12 | 胶囊正确呈现稍后、当天跳过和已完成状态；alarm 失败不伪造成功，下次打开/恢复仍可提示。 |
| AC-13 | 修改或删除餐食后首页与历史立即回算；应用重启后已确认记录仍保留。 |
| AC-14 | 清除需二次确认，完成后档案、记录、最近项、收藏和餐时状态不可见。 |
| AC-15 | 全应用无真实录音、云端 ASR、系统级灵动岛、手机同步或医疗能力宣称。 |
| AC-16 | 深色表盘背景、暖橙餐食状态、绿色完成状态、大数字和圆角卡片清晰一致；以 480×480 圆屏为主，并检查方屏和窄屏不溢出。 |
| AC-17 | 摄入 1200、饮食参考线 2000 时，差值为 800，进度为 60%；旧运动数据不影响上述任一结果。 |
| AC-18 | 首页显示单一摄入进度、三餐文字状态和连续记录天数；最近 7 天正确计算有记录天数、有记录日平均摄入与每日已记录餐数。 |
